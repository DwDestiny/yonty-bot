# 定时任务

> 2.0.0 · 2026-11-22 · 维护：Yonty Bot contributors

定时任务按时间表叫醒一个后台任务，到点跑一次，跑完留下下次怎么跑。创建、权限、看和停都在这里。

## 1. 怎么建

主人在聊天里说想定时做什么，主控写一个 `[定时]` 块。格式同 `[派活]`，多下面这些字段。

```
[定时]
名字: 早报
仓库: ~/work/<仓库目录>
时间表: cron 0 9 * * *
上下限: 每 30 分钟 ~ 每天
探针: ~/bin/check.sh
类别: 普通
范围-读: ~/work/<仓库目录>
范围-工具: Read, Grep, Bash
范围-命令: git log
发给: 主人
预算: 3（依据）
任务书:
……
```

| 字段 | 写什么 |
|---|---|
| `名字` | 短名，编号是 `短名#S1`、`短名#S2` |
| `时间表` | 见第 2 节 |
| `上下限` | 最快和最慢多久跑一次，`[下次]` 只能在里面调 |
| `探针` | 见第 4 节，不写就每次都跑 |
| `类别` | `普通` 或 `安全`。安全类不能自己加快、扩大 |
| `范围-读`、`范围-工具`、`范围-命令`、`范围-MCP`、`范围-设备`、`范围-动作`、`范围-分支` | 权限范围，见第 5 节 |
| `发给` | 结果发给谁，按投递规则收，见 architecture.md |
| `预算` | 每次运行的检查点 |

## 2. 时间表和时区

时间一律按北京时间，由配置 `timezone`（默认 `Asia/Shanghai`）决定。

| 写法 | 意思 |
|---|---|
| `cron 0 9 * * *` | 每天 9 点 |
| `每 30 分钟` | 间隔 |
| `一次 2026-11-23 09:00` | 只跑一次 |
| `自定 首次 <时间>` | 首次跑的时间写死，之后全由运行里的 `[下次]` 定 |

## 3. 上下限和 `[下次]`

每次运行的最后写一段 `[下次]`：

```
[下次]
时间: 2h | 2026-11-23 09:00 | 按计划 | 停
理由: 一句话
范围: 下次要用的范围（可不写）
结果: 正常|异常|已处置
```

- 放慢、收窄、停掉：直接生效。
- 加快、扩大：只记成提议，等主人或创建者批。
- 没写 `[下次]` 的按时间表走。写的时间超出上下限，按上下限截。

## 4. 探针

探针是一条便宜的命令，先于智能体跑。输出一行 JSON，`wake` 为真才叫醒智能体，否则这次跳过，不花令牌。

```
{"wake": true, "note": "有 3 条新告警"}
```

## 5. 权限范围

- 范围各栏不能超过创建者自己。主控创建时受主控的限制，任务里创建受任务的限制。
- 私密目录只有“主人私聊里的创建者”能放进 `范围-读`。同事、群里创建的不行。
- 运行时的环境变量：`FCB_OWNER=0`（定时运行不当主人）、`FCB_SCHEDULE`（运行编号）、`FCB_SCOPE`（范围文件）。钩子按它们拦，见 boundary.md。
- 读范围用 bwrap 落实，钩子（`private_guard`、`scope_guard`）是第二道。原因和实测见 boundary.md“沙箱实测”。
- 机器上没有 bwrap 时，带读范围的定时运行不跑。装法：`apt install bubblewrap`。

## 6. 运行规则

| 情形 | 做法 |
|---|---|
| 上一次还没跑完，下一次到点 | 跳过，不叠加 |
| 服务停了一段时间，错过多次 | 只补最近一次 |
| 单次运行太久 | 超过 `schedules.max_run_min`（默认 120）停掉 |
| 连续失败 | 达到 `schedules.fail_pause`（默认 3）次暂停，并投递给创建者 |
| 升级服务 | 不开新运行，等在跑的跑完 |

## 7. 看和停

| 命令 | 作用 |
|---|---|
| `/schedules` | 列出全部定时任务、下次时间、状态 |
| `/schedule pause 短名#S1` | 暂停 |
| `/schedule resume 短名#S1` | 恢复 |
| `/schedule stop 短名#S1` | 停掉并删除 |

## 8. 看门狗

看门狗是一个单独的 systemd 定时器，不依赖 bridge。它定期检查 bridge 活着、定时运行没有卡死，出问题时重启服务并私聊主人。scaffold 只生成单元文件，不启用，启用步骤见 guide.md 的 2.0.0 升级说明。
