# 怎么用：按场景

> 3.18.0 · 2026-11-25 · 维护：Yonty Bot contributors

装好以后怎么跟它说话、它会做什么、什么情况下停下来等你。每个场景给一句可以直接复制的话，示例里的仓库和人名都是虚构的。还没装好，先看 [quickstart.md](quickstart.md)。

说明：

- “你”指主人，装机器人的人。“同事”指别人。
- 命令表和内部标记的完整写法在 [tasks.md](tasks.md)，这里只讲怎么用。
- 出了问题按现象查 `docs/troubleshooting.md`。
- 这些场景在代码和文档里核对过。没有在真实项目上长期跑过的，在“限制”一节列出。

## 1. 问问题

私聊机器人，或在群里 @ 它。同事 @ 它问问题不用你批，它直接起会话回答，会读这台机器上的代码。

```
@小助理 订单模块里 cancel_order 在哪定义的？取消后库存是在哪一步回补的？
```

- 私聊它收全部消息；群里只收 @ 它的。
- 它会带最近的聊天前文：飞书群默认最近 2 小时最多 20 条，私聊 24 小时。企业微信没有前文，要靠消息本身说清。
- 私聊闲置 6 小时，或者你发 `/new`，换新会话。群里闲置 2 小时换新。
- 几分钟能完的小改动它会在聊天里直接做，不派后台任务，也就没有下一节的验证闸门。

## 2. 派活

十几分钟以上、要改不少代码的活，它不会在聊天里硬干，而是先把事聊清楚：目标、范围、怎么算做完，再派成后台任务。

你的活，主控交给这个项目的项目经理：项目经理读代码、出方案、拆任务、派工、验收。同事的活不一样：主控写好任务书，等你批了才开工。

```
给 demo-shop 加一个“满 200 减 20”的优惠。规则在 docs/promo.md，结算页要显示减了多少。
验证命令用 python3 -m unittest。做成后开合并请求，我来合。
```

要点：

- **写清验证命令**。这是后面“验证闸门”的前提。没有的话，它会问你，或者任务带着“没定验证命令”结论回来。
- 任务在自己的工作树和 `bot/` 分支上跑，不碰你正在用的目录。几个任务不会抢同一块文件。
- 分支叫 `bot/<短名>-<N>-<月日>`。任务编号是 `短名#N`，例如 `demo-shop#3`。短名默认取仓库目录名，各项目各自从 1 编。
- 合并请求只建草稿，不合并。支持 GitHub（要装 `gh`）和阿里云 Codeup；别的平台它给你分支名。同事触发的任务只能推 `bot/` 分支。
- 后台任务到预估花费就停下来交回，由主控决定续不续。

## 3. 批准同事的活

同事派的活要你批才开工。群里派的，机器人在同一个群里 @ 你，附任务书快照；私聊派的，它私聊你。

```
@小助理 /approve demo-shop#4
@小助理 /reject demo-shop#4
```

- 只认你的发送人 ID。同事自己发 `/approve` 会被拒。
- 24 小时没人批，任务作废。
- `/task brief demo-shop#4` 看完整任务书。审批消息里超过 3000 字的部分被截掉了。

## 4. 补充、取消、看进度

```
demo-shop#3 再加一条：优惠不能叠加会员折扣
/task demo-shop#3
/tasks
/task cancel demo-shop#3
```

- `短名#N 内容` 把话塞进正在跑的任务；任务已经等回复、完成、失败或中断，会接着同一个会话再跑。你发的直接转；同事发的先交给主控，由主控决定转不转。
- 群里要 @ 机器人。只写 `#3` 有歧义时（两个项目都有 3 号），它列出候选，什么都不做，请带上项目名。
- `/task cancel` 停掉任务，分支留着；`/task clean` 删工作树，分支留着。
- 任务问你问题时会写“[提问]”并停下，任务变“等回复”。直接回答，或者用 `短名#N 你的回答`。
- 想知道为什么没开工：`/why demo-shop#3`，看放行或改投的理由。开新任务前服务看内存余量，放得下才开。
- 不想让它干了：`/stop` 全部停工，`/stop demo-shop` 只停一个项目，`/resume` 复工。主人私聊里单发“停”也算。
- 一个任务的结束消息第一行是结论：`PASS`、“没定验证命令”、`BLOCKED` 或“到检查点”。主控会用自己的话转给你，不是原样转发，所以你不会总在消息第一行看到 `PASS` 这个词；要核对就 `/task 短名#N`。

## 5. 验证闸门：说做完，不算数

任务写了验证命令时，智能体说“做完了”以后，服务再自己跑一遍这条命令：

1. 命令通过，结论写 `PASS`（服务复跑验证命令通过）。
2. 没通过，把输出末尾退回同一个会话返工。默认最多退回 2 次（`tasks.verify_retries`）。
3. 返工后还不过，按失败交回，结论写 `BLOCKED`，附原因和输出。

它保证的是“你定的那条命令，服务看到它通过了”。命令测不到的东西它保证不了，所以验证命令要写得有区分力。

注意几点：

- 默认的 Claude 任务是自己先推分支、建草稿合并请求，说做完之后服务才复跑验证。验证没过时，草稿可能已经在那里。`PASS` 才说明验证通过，合并请求是不是该合，由你定。ZCode 和云端的任务反过来：服务复跑过了才建合并请求。
- 日志在 `<tasks.root>/gates/<任务 id>/gate-<n>.log`（默认在 `~/work/.bot-tasks/` 下）。

### 5.1 没写验证命令会怎样

结论写“没定验证命令，服务没复核”，任务直接算完成，合并请求照样建。派活时写了验收命令的，用它当验证命令。别的情况，服务不会替你想一条。

只读的角色（评审、产品、需求）在分支上没有提交时也不跑验证。

所以重要的活，派之前先说清验证命令。已经交回的，要再核一遍，就让它重新派一个带命令的任务。

### 5.2 中途换验证命令

任务跑到一半发现命令写错了：告诉它新命令。项目经理或主控写 `[改验证] 短名#N 命令` 后，闸门用新命令。完成回报里的结论会写“验证命令中途换过，原来是 …”，换了什么留得下记录。

```
demo-shop#3 验证命令改成 python3 -m unittest tests.test_promo
```

### 5.3 几个例外

不是每次没过都退回两次：

- **服务自动选模型的活**（本机跑、有验证命令的开发活）：从 sonnet 起步，验证第二次没过，服务换更强的模型从同一个分支再来。再不行升到 opus 的最高一档（xhigh）为止。你在聊天里点名模型（例如“用 opus”）时，写成“主人指定”，不自动升。
- **两次失败的是同一批测试**：不再退回，直接 `BLOCKED`。再退回一次也是白跑。
- **验证没跑完**（超时、缺依赖、测试环境出问题）：结论写 `BLOCKED（验证没跑完，不是没通过，没返工）`，不返工，不换模型，交给上级处理。验证命令超过 20 分钟（`tasks.verify_timeout_min`）也会叫上级看。
- **ZCode 试点的任务**：只给一次机会，不过就换 Claude 接着干。试点默认关，见 [tasks.md](tasks.md)“智能体适配层”。
- 交回内容里写了“按失败交回”，服务按它结束，不再复跑。
- 云端任务：到本机复跑，没过按 `BLOCKED` 交回，没有换人的机会。

## 6. 独立验收：写代码的人改不了验收测试

适合验收标准能写成测试、做错代价大的活：新功能、改行为、会影响用户的 bug。派活时说一句：

```
给 demo-shop 加运费计算，满 99 包邮。要独立验收：先由别人写好测试，再开工。
```

指令里写的是 `验收: 独立`。服务会：

1. 先用验收角色开一个新会话，看任务书和现有代码，写测试并提交。
2. 记下这次新增的测试文件，锁起来。
3. 再开负责人的会话写代码。负责人一改这些文件，验证闸门就退回它。
4. 验证命令和验收命令不同时，各跑一遍。

使用时要知道：

- 只锁验收新增的文件。验收改了已有文件的，会告诉负责人，不锁。
- 要有验证命令或验收命令，闸门才拦。没有命令时只在结论里写出改了哪些。
- 验收没写出测试，或者角色模板缺了，任务照常开工，结论行写“没有独立验收”。云端任务不做独立验收，改在本机跑。
- 测试本身写错了：负责人会 `[提问]` 说明。你或主控回“放开验收测试”后不再锁；同事回不算。
- 小改动、纯文档、机械活不用，白花一段额度。
- 这套做法有自动化测试（用假 CLI），在真实项目上跑的数据还在积累。

## 7. 按版本干活：方案、并行、一个合并请求

项目类的活按版本走：一个版本一个方案、一个合并请求，测试、评审、发版每个版本只做一次。

你说需求，项目经理出方案：定版本号、拆成小任务、标明哪个任务动哪些文件、谁依赖谁。然后：

- 小任务并行：每个任务独占自己的文件，文件撞了、依赖没完成的排队。每个项目默认最多同时 4 个（`team.max_parallel`）。
- 小任务只推分支，不各建合并请求。最后一个收口任务把分支合到一起，跑全量测试，建唯一一个草稿合并请求。
- 新需求点补进正在做的方案，不另开一套。线上急修、互不相干的仓库才另开。
- 只有一个任务就做得完的小活，方案写 `版本: 临时`，不派收口；一个项目一天最多 3 个。
- 方案的花费到预警线（`预算: N`，没写按 `tasks.quota_alert.plan_usd`）的 1 倍、1.5 倍、2 倍等会私聊提醒你，不停活。
- 一件事一个负责人：同一块长期的工作（例如“登录”“支付对账”）总交给同一个负责人。会话还热就接着上次干，凉了就读档案（现状、待办、决定）。同一件事同时只跑一个任务，后来的排队。

```
登录这块我要做第三方登录。先出方案，拆开并行做，别一个个来。
```

小任务的开工、进展、完成直接发到你的私聊，不经过模型。看 `/tasks` 或 `/team`。

## 8. 旁听：没 @ 它的话它也看

只在飞书群里有，由你逐群打开。默认所有群都不旁听。

```
@小助理 /listen on
@小助理 /listen off
@小助理 /listen status
```

- 打开后，服务约每 40 秒拉一次群里的新消息，安静 25 秒后整批交给 Claude，由它决定接不接话。默认不出声。
- 它会插话的情况：有人点到它或你、有人卡在一个它明确能答的问题上没人答、有梗可接。插话后 10 分钟内不再主动插话。
- 旁听会话按“不是你”的权限跑，即使批里有你的发言。
- 企业微信没有旁听：平台只推私聊和群里 @ 机器人的消息。

> **注意**：可选的“决策点”（`decide`）默认关。你把 `decide.enabled` 改成 `true`，模板里的旁听判断就开始向你配置的后端发送旁听群的消息：发送人名字、用户 ID 和文字，加上机器人和你的名字、守则里“群聊旁听”那一节。手机号、邮箱、IP 不会去掉。`haiku` 后端会把这些内容发给 Anthropic，`rules` 后端只在本地判断，`jev` 和 `openai` 发到对应的地址。要关，把 `decide.enabled` 设成 `false`，重启服务。字段见 [config.md](config.md)。

## 9. 定时任务

让它按时间表做事，例如每天早上看一眼：

```
每天早上 9 点看一下 demo-shop 的 CI 有没有红的，有就告诉我；只读，不要改代码。
```

- 时间一律按北京时间（`timezone`）。支持 cron、间隔、只跑一次。
- 每个定时任务带自己的权限范围（读哪些目录、用哪些工具和命令），不会超过创建它的人。带读范围的运行要 `bwrap`，没装就不跑。
- 连续失败 3 次自动暂停。
- `/schedules` 看列表。创建、时间表、探针、权限范围和怎么停，见 [schedules.md](schedules.md)。

## 10. 飞书任务同步

默认关。打开 `feishu_tasks.enabled` 后，你私聊派的活会同步成飞书任务：机器人负责、你关注，状态和结论由服务照任务状态写。你在飞书任务里把任务指派给机器人，等于私聊派活。要先给应用开通任务相关权限，清单见 [config.md](config.md) 的 `feishu_tasks.enabled`，原理见 [tasks.md](tasks.md)“飞书任务同步”。

## 11. 云端执行

大活儿可以跑在 Claude 官方云端，不占这台机器的内存：

```
这个活派云端执行。
```

条件：配了 `tasks.cloud.environment_id`；派活的是你本人；仓库远端是 GitHub。不满足，改在本机跑。云端不省订阅额度，也没有本机的钩子，公司私有仓库别上云。做完把分支拉回本机复跑验证命令，没过按 `BLOCKED` 交回。见 [tasks.md](tasks.md) 6.4。

## 12. 额度和预算

- 费用：Yonty Bot 免费（MIT）。用的是这台机器上登录的 Claude 账号和额度，谁 @ 它都一样。官方目前把 `claude -p` 计入订阅额度，规则可能变，用词是 “For now”，以[官方说明](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)为准。
- 任务里的“美元当量”是命令行按 API 标价算的，只用来比较任务大小，订阅不按它收费。
- 任务到预估花费会停下交回，由主控或你决定续不续（`短名#N 继续，预算加到 X`）。聊天没有这个上限。
- 订阅额度用得比时间快会私聊提醒你，只提醒。
- 额度用到 95%（`tasks.quota_pause`）或撞限额时，服务把在跑的 Claude 任务退回排队，只私聊你一条，等刷新后自动接着干。你可以回“换 ZCode”换人干，或 `/quota go` 把剩下的用完，`/quota` 看状态。
- 补丁版默认自动装（`updates.enabled: true`）：Yonty Bot、lark-cli、wecom-cli、mcporter。Claude Code 和非补丁版先问你。要关设 `false`。

## 13. 限制

- 小改动在聊天里直接做，不走验证闸门。要闸门就明说“派成后台任务”并写验证命令。
- 没写验证命令的任务没有复核，`PASS` 只出现在写了命令且通过的任务上。
- 钩子按命令文字拦，挡得住直接做法，挡不住先写脚本再执行这类绕法。主干要靠 GitHub 的分支保护兜底：开“必须经合并请求”“禁止强推”，机器人用的账号不要给绕过权限。见 [boundary.md](boundary.md)。
- 没有发送人名单：谁能找到机器人由飞书应用的可用范围决定；群里别放你不信任的人。
- 默认的聊天和任务不在沙箱里，和你用同一个系统用户，能读这台机器上的登录凭据。
- 只有 Claude Code 是主线。后台开发任务有一个默认关闭的 ZCode 试点，Codex 还没有实现。
- 企业微信没有前文和旁听。收发在 2026-11-20 的实测里通过，本期没复测。
- Mac 可以试，合盖就收不到消息；看门狗和 `/upgrade` 依赖 systemd，Mac 上没有。没实测。
- 没有网页后台，文档以中文为主。
- “读档案接手”和“独立验收”已有自动化测试，真实项目上的数据还在积累。云端执行和 ZCode 试点没有成绩数据。

## 14. 命令表

发 `/help` 看当前能用的。常用的：

| 命令 | 谁能用 | 作用 |
|---|---|---|
| `/tasks`、`/task 短名#N` | 所有人 | 列表、单个任务的进度 |
| `/task brief 短名#N` | 能看到的人 | 完整任务书 |
| `/task cancel 短名#N` | 你、派活人 | 取消，分支留着 |
| `短名#N 内容` | 你、派活人 | 补充或回答 |
| `/approve`、`/reject 短名#N` | 你 | 批不批同事的活 |
| `/why 短名#N` | 你 | 为什么排队或改投 |
| `/stop [短名]`、`/resume [短名]` | 你 | 停工、复工 |
| `/listen on｜off｜status` | 你（飞书群里 @ 它） | 旁听开关 |
| `/quota` | 你（私聊） | 额度和暂停后的选择 |
| `/status` | 你（私聊） | 额度、在跑的任务、最近报错 |
| `/new` | 私聊 | 换新会话 |
| `/team`、`/schedules`、`/updates`、`/upgrade`、`/retro` | 你 | 角色、定时任务、更新、升级、复盘数据 |

完整表和说明见 [tasks.md](tasks.md) 第 2 节。
