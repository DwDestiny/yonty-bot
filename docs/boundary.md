# 边界：人设、身份、私密资料

## 1. 三层防线

| 层 | 管什么 | 靠什么 |
|---|---|---|
| 守则 `rules.md` | 什么能说、对谁说、什么事要主人点头 | Claude 自己判断 |
| 钩子 `lark_identity.py` | lark-cli 用哪个身份 | 硬拦，exit 2 |
| 钩子 `wecom_guard.py` | wecom-cli 能调什么 | 硬拦，exit 2 |
| 钩子 `private_guard.py` + 权限拒绝表 | 私密路径能不能读 | 硬拦 |

守则管“说不说”，钩子管“碰不碰”。能用钩子拦的就别只靠守则。

## 1.1 威胁模型（2026-11-23）

评审按这一节判“必修”：能在“防”里的条件下做到“防”里的事，才是必修；“不防”里的事不算，但文档不能把它写成防住了。

**防谁**：同事发来的消息；网页、文件、日志、issue 这类外部内容里夹带的指令。它们能驱动会话和任务去跑命令、写文件、调 `tasks.py`，但过得了钩子和沙箱的才算。

**防什么**：

| 事 | 靠什么 |
|---|---|
| 越权：同事触发的会话、任务、定时运行做了只有主人能做的事 | 主人权限只来自两处：bridge 收到的 IM 消息；服务从自己启动的运行的输出里解析出的回报、提问、投递、`[任务指令]`、`[派活]`（身份取任务记录）。主人在 IM 里答复会话的请求，只有请求是主人自己的私聊会话发的、又在同一个私聊里答复，那一轮才带主人权限；答复别的会话（同事私聊、群、同事触发的项目经理）只送文字。命令行（`tasks.py send/act/inbox/mr/diag`）来的一律不带主人权限，不管认出是谁 |
| 泄露：私密资料、主人私聊、别人的收件箱被读到 | 私密路径钩子和拒绝表；定时运行的沙箱；收件箱按进程认归属（单元的 MainPID 加 InvocationID） |
| 冒充主人：伪造投递、审批、身份 | 同第一行；投递记录的主人身份要有 bridge 内存里钥匙的签名 |
| 丢消息：投递、答复、审批说送到了其实没有 | 投递先落盘，处理完才算送到，失败重送；沙箱里的请求以服务的回执为准 |
| 定时运行逃出范围：读范围外的文件、写工作树以外的东西、让服务替它在箱外写或执行 | bwrap 沙箱；箱里除工作树、发件箱、会话记录外没有可写的；服务按范围校验后在箱外执行 |
| 设备红线：设备上跑 Claude、碰登录态 | 设备侧包装脚本是主防线，`device_guard` 是第二道 |

**不防**：

- 主人自己派的任务蓄意作恶。主人派的任务有主人给的权限，能直接改代码、跑命令，拦它没有意义。
- 同一个系统用户直接改任务记录（`state/tasks/<id>/task.json`、`events.jsonl` 这类）。服务和任务是同一个用户，文件权限分不开；`private_guard` 按文字拦，挡得住直接写，挡不住绕法。任务记录是信任的起点。
- 已经绕过钩子、以本用户执行任意代码的进程（写脚本再执行、`python -c` 拼出来的命令、`ptrace`）。它能读服务的内存和文件，要防得换系统用户或虚机，不在这一层做。定时运行不在此列：它在沙箱里，执行任意代码也不能出箱。
- 主人的电脑、IM 账号、GitHub 账号被别人拿到。

## 2. 场景怎么判断

bridge 给每次调用设环境变量，钩子据此判断：

| 变量 | 值 |
|---|---|
| `FCB_OWNER` | 1 = 发消息的是主人本人 |
| `FCB_PRIVATE` | 1 = 主人本人的私聊（只有这里放开私密资料）。主人答复会话请求叫起来的那一轮，只有主人自己的私聊会话、在同一个私聊里答复才是 1 |
| `FCB_CHAT_ID` | 当前会话的 chat_id |
| `FCB_CHANNEL` | `feishu` / `wecom`，消息从哪个渠道来 |
| `FCB_LAYER` | `pm` = 项目经理那一轮。`scope_guard` 拦 Edit、Write、NotebookEdit，`device_guard` 拦设备 |
| `FCB_SCHEDULE` | 定时运行的编号，只在定时运行里有 |
| `FCB_SCOPE` | 范围文件 `state/schedules/<id>/scope.json`。`scope_guard` 按 `范围-工具` 拦，`private_guard` 只放 `范围-读` 里的私密路径，`mcp_guard` 只放 `范围-MCP` 里的服务器 |

主人在群里 @ 机器人，`FCB_PRIVATE` 仍是 0：群里有别人看着。主人在群里答复自己私聊会话的请求，那一轮也是 0，会话的回话改发主人私聊，不发进群。非私聊场景还会设 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`，不读不写自动记忆。

## 3. 身份策略（config.json 的 identity）

| 字段 | 值 | 含义 |
|---|---|---|
| `owner` | `user_no_speak`（推荐） | 主人布置的事可以用主人身份办（日历、文档、会议室），但不能以主人名义发、改、撤消息 |
| | `user` | 完全放开 |
| | `bot` | 只用机器人身份 |
| `others` | `bot_read_im`（推荐） | 同事触发时，只有读聊天记录能用主人身份（机器人读不了群历史），其余只能用机器人身份 |
| | `bot` | 只用机器人身份；前文也读不到别的群 |

> **警告**：`bot_read_im` 下，同事 @ 机器人时，机器人能用主人身份读到主人和别人的私聊。挡住转述靠守则。主人对某些聊天有顾虑时，在 `lark_identity.py` 里加 chat_id 黑名单，或改用 `bot`。

### 企业微信（hooks/wecom_guard.py）

wecom-cli 带着主人的企微授权（读邮件、文档、日程、微盘），本机装了它，飞书会话也能调用。钩子总是挂上：主人本人发的可用，但不能以主人名义发消息和邮件；其他人只能用 `wecom-cli message aibot` 和 `wecom-cli contact`。细节见 [wecom.md](wecom.md) 第 4 节。

### 跨 IM 读取（config.json 的 cross_im_read）

两个渠道都启用时才有意义，默认关。

| | 关（默认） | 开 |
|---|---|---|
| 飞书会话读企微聊天记录（`wecom-cli chat`） | 拦 | 可以 |
| 企微会话用主人身份读飞书聊天记录（`lark-cli im +chat-messages-list` 等） | 拦 | 可以 |

开了以后，同事触发时能不能跨读，仍按 `identity.others`：`bot_read_im` 能读，`bot` 不能。

> **警告**：打开前要让主人确认：读到的内容会不会被转述到另一边，只靠守则和 Claude 把关。`scaffold.py` 第一次遇到打开的配置会打印提醒并停下，主人同意后加 `--confirm-cross-im` 再运行，确认记在实例的 `state/cross_im_confirmed`。

## 4. 旁听的权限

旁听由 bridge 用主人的用户身份定时拉白名单群的消息，所以：

- 主人必须在这个群里；`context.read_as` 是 `bot` 时旁听拉不到消息。
- 不需要开“读取群内所有消息”权限，非白名单群收不到任何没 @ 的消息。
- 旁听批次一律按“非主人、非私聊”跑（`FCB_OWNER=0`、`FCB_PRIVATE=0`），即使这批里有主人的发言，私密资料和主人身份都不放开。
- 只有主人能开关，命令在群里发，回复也只在那个群里。

## 4.1 长任务的权限

- 权限按派活人定，建任务时写进 `task.json`，之后谁补充指令都不变。同事派的活即使主人批了，也按“不是主人本人”跑：私密路径照拦，git 只能推 `bot/` 分支，gh 只能建草稿合并请求。
- 只有主人能批；补充指令、回答提问、取消只认主人和派活人本人（按发送人 ID）。
- 所有任务都不合并、不推主干、不发版。细节见 [tasks.md](tasks.md) 第 3 节。
- git 护栏挡得住直接的绕法，挡不住写脚本再执行这类间接绕法。主干要靠 GitHub 分支保护兜底。

### 设备（hooks/device_guard.py）

- 调用设备的命令用正则匹配（`devices[].match`）。文字里哪个词的开头匹配得上，就看这一段是不是能确定的普通用途；确定不了就按设备命令处理，红线、租约、身份三样用同一套识别，宁可误拦。
  - 认得到的写法：`timeout`、`nice`、`stdbuf`、`setsid`、`xargs`、`ssh`、`env -u`、`sudo -u`、`watch`、`find -exec` 这类套在前面的；`$(…)`、反引号、`<(…)` 里的；`sh -c`、`eval`、管道给 shell 的文字；函数体、`case`、`alias`、`trap`；绝对路径；引号、反斜杠、`$'…'`、空替换、`$(printf 字面)` 拆开的设备名；本命令里赋值的变量。
  - 普通用途：注释；`echo`、`printf`、`grep`、`rg`（不带 `--pre`）、`cat`、`ls`、`cd`、`which`、`find`（不带 `-exec`、`-delete`）、`sed -n 行号`、git 的常用子命令（不带 `-c`、`-x`、`--exec`、`-O`）、gh、lark-cli、wecom-cli 等；给普通变量赋值；路径中间的一级目录（`/x/devcli/tool.py`）。同一条命令里还有把文字当命令跑的（shell、`xargs`、`ssh`、`eval`、`source`、拿变量当命令、`alias`、函数定义），普通用途也不算。
  - 会误当成设备命令的例（同事触发的会话拦下，主人的和任务的要占租约）：`cp devcli x`、`vim devcli.conf`、`bash build.sh && grep devcli notes`。参数从 `xargs` 来的设备命令算不出，谁都拦。
- 任何设备上都不运行 `claude`，不打开 claude.ai。设备命令去掉引号和反斜杠后带 `claude`、`anthropic` 字样的（含 `claude-code`、`@anthropic-ai/…`）一律拦；不是直接写在命令开头的、有管道或 heredoc 的，查整条命令。变量和命令替换只在算不出结果时才拦：同一条命令里用字面值赋过的变量、`for` 的字面列表会代进去再查（每个可能的值和空值都查一遍）；`$HOME`、`$USER`、`$LOGNAME`、`$HOSTNAME`、`$?`、`$$`、`$#`、`$!`、算术，以及 `date`、`whoami`、`hostname`、`id -u`、`uname`、`uuidgen`、`nproc`、`mktemp`、`seq` 这几个的替换放行。
- 设备命令里算不出、会拦的：没在同一条命令里赋值的变量（`$CMD`）、`$1`/`$@`（含 `awk '{print $2}'`）、`${x:-…}` 这类展开、别的命令替换（`$(cat f)`、`$(git …)`）、`$'…'`、`<(…)`、`read`/`+=`/`printf -v` 赋的变量、通配符的 `for`、同一条命令里又 `source`、`eval`、定义函数、改 `PATH` 的。改成把值直接写出来。
- 设备的 MCP 工具按 `devices[].mcp`（MCP 服务器名）认，参数里带 `claude` 或 claude.ai 的拦。
- 钩子只看得到命令文字，挡不住写脚本再执行、`python -c` 拼出来的命令、通配符拼的命令名（`devc?i`）。设备上要装 `scripts/device-wrapper.sh` 做主防线：设成 SSH 的 `command=` 或设备上远程命令的入口，它拒绝以 `claude` 名义运行、拒绝命令或参数里带 `claude`、claude.ai 的（退出码 126），其余照常执行。
- 身份：主人私聊会话短时可用（一轮 10 次、3 分钟）；主人派的任务独占租约；同事来源一律拦；项目经理不用设备。
- 租约在 `state/devices/<名字>.json`。重置命令只给占用者；任务离开“进行中”就释放。定时运行的沙箱里看不到租约：钩子把请求写进发件箱，服务按任务的范围在箱外取，等到回执才放行。

### 动作

`tasks.py act` 办修补、授权、花钱、方向、禁止这几类事，定义在 `actions/<名字>.json`。命令行提交的不带主人权限：只有登记了 `coworker_ok` 的修补类直接跑，其余写审批单。主人私聊里主控写 `[服务命令] act <名字> --参数 值`，由服务执行，修补类直接跑。授权类要主人 `/approve 短名#N.aK` 批。

### 权限范围

定时运行带一份范围文件，各栏不能超过创建者。见 [schedules.md](schedules.md)。

### 不可逆闸门（hooks/irreversible_gate.py）

命令不可逆、而任务还有没取的追加指令时，闸门拦下，先取指令再动手。内置的判断按参数解析（拆 `;`、`&&`、管道、`sh -c`、`eval`，跳过 `env`、`sudo`、`git -C` 这类前缀和全局选项；前面套着 `timeout`、`ssh` 之类的也认；`$(…)`、反引号、`<<<`、`alias`、`git config alias.x`、函数体里的也拆开；引号外的 `#` 注释和反斜杠续行先去掉；`echo`、`grep` 这类只是打印、搜索的不算，除非同一条命令里有 shell、`xargs`、`ssh` 在跑文字；`python -c`、`node -e` 的代码按文字扫）：`git push` 推标签、`--mirror`、`--all`、推到版本号或发布分支（stable、release、release/*、production、prod），`--repo=` 写远端的也认；推的目标有变量、命令替换、花括号，或者从 `xargs` 来，算不出就按命中；`gh -R o/r` 写在哪儿都认；`gh release` 的改动类子命令；`gh api` 对 `releases`、`git/refs`、`git/tags` 发非 GET 请求（方法不分大小写）；npm、pnpm、yarn、bun、cargo、poetry、flit、hatch、twine、gem 发包。命令拆不开时按文字扫。`config.json` 的 `irreversible` 里的正则照样合并进来。

### 沙箱实测（2026-11-22）

目标：定时运行只能读范围内的目录。

- 用户级 systemd 单元（systemd 255）里，`ProtectHome=tmpfs`、`BindReadOnlyPaths=`、`InaccessiblePaths=` 不生效：单元照样读得到被藏的文件，systemd 不报错。
- 所以读范围改用 bwrap 落实：Claude 进程外包一层 bwrap，盖住范围外的目录和 `/run/user`，只放回该看的（现在的清单见下一节）。
- `/run/user` 必须盖：没盖时，沙箱里用 `XDG_RUNTIME_DIR=/run/user/<uid> systemd-run --user --pipe --wait cat <范围外的文件>` 读得到（2026-11-22 实测），用户级 systemd 在沙箱外替它跑命令。
- 探针比定时运行收得更紧（探针不经过钩子）：家目录、`/tmp` 整个盖掉，只读放回该看的，见 schedules.md 第 4 节。测试 `test_probe_sees_only_scope_and_no_credentials` 用真的 bwrap 验证范围外的文件、凭据目录、实例目录和用户级 systemd 这条路都走不通。
- 机器上没有 bwrap 时，带读范围的定时运行不跑，不降级成只靠提示。

### 定时运行的沙箱（评审修复 2、3，2026-11-23）

- 整机只读（`--ro-bind / /`）。家目录、`/tmp`、`/run/user` 盖成空目录，`docker.sock` 盖掉。
- 只读放回：仓库（连同它的 `.git`）、范围-读、`~/.claude`、git 配置、PATH 里的目录、每个 `claude` 的真实目录、Python 前缀、`tasks.sandbox_read`。
- 实例目录盖成空目录，按白名单只读放回（`tasks.py` 的 `INST_KEEP`）：`*.py`、`hooks/`、`roles/`、`actions/`、守则、`config.json`、`claude-settings.json`、`yonty-bot.json`。`inbox/`（主人私聊的附件）、`logs/`、旁听名单、`_tmp/` 和以后新加的文件都看不到。`state` 只放回本任务目录和范围目录。盖上的目录最后变只读，放不进假模块。写在实例目录下的范围-读不放。
- 可写：工作树；本任务的发件箱 `outbox.jsonl`；自己的会话记录目录；`tasks.sandbox_write`。`~/.claude.json` 换成本任务的副本。`state` 整个只读，锁文件盖成 `/dev/null`（只读文件也能加锁，看得见就能占着锁卡住服务）。进程号命名空间是单独的（`--unshare-pid`）。
- 投递、动作、设备租约、收件箱回执都写进发件箱（`outbox.py`），服务在箱外办：归属只看是谁的发件箱，不信行里的字段；投递只能给范围里的 `发给`（和只进记录的），动作要在 `范围-动作`、参数合规，设备要在 `范围-设备`；定时运行的命令行投递一律不带主人身份。办完写回执 `outbox.ack.jsonl`（箱里只读），箱里的命令等到回执才说成功，等不到（`tasks.outbox_wait_s`，默认 60 秒）就说“不算办成”、非零退出。一行坏 JSON、类型不对、太长只跳过它自己；同一个请求重放不办两次，动作先记进 `outbox.claim` 再跑，同一拍写两行、跑到一半服务重启后重放都只跑一次。发件箱在单独线程里分批办：每个任务一拍最多 `tasks.outbox_batch_s` 秒（默认 3）、最多 4 个动作同时跑，没办完的留在发件箱里下一拍接着，投递和放行最多等它 1 秒。
- 服务写状态文件都走 `fsio.py`：随机临时名加 `O_EXCL|O_NOFOLLOW`，再改名换上；追加和加锁也不跟软链接。
- 私密目录看不全就不放回：放回的每个目录最多看 `tasks.walk_max`（默认 20 万）个文件和目录，正则写的私密路径要在里面找，`node_modules`、`.venv`、`__pycache__`、`.git` 也找。超过了，必须有的（仓库、工作树、范围-读、`~/.claude`）按失败交回并写明是哪个目录；可有可无的（PATH 里别的目录、`tasks.sandbox_read`）不放回，记决策日志。探针的沙箱同样处理，第一次就告诉主人。
- 工作树是独立的 `git clone --shared`，主仓库整个只读，沙箱里改不了主仓库的分支、配置和对象。clone 的 `.git` 归任务写，里面能藏要执行的命令，也能把 `objects`、`refs` 换成指向别的仓库的软链接，所以沙箱外一条 git 都不对它跑：角色检查的 git 在沙箱里跑；每轮结束服务把 `bot/` 分支 fetch 回主仓库，对面的 `upload-pack` 也在沙箱里跑；在 clone 里跑 `tasks.py mr` 会先切到主仓库；清理直接删目录，分支没拉回来就不删。
- 等人回话时的会话压缩也在沙箱里跑。定时运行不做独立验收。任务回报里写明看改动、推送都到主仓库做，也不给“终端接手”命令：别在 clone 里直接跑 git 或 Claude。
- 私密路径最后盖：字面路径整机盖；正则在放回的目录树里找（解析软链接）。范围-读明确列的私密目录放开；只列了私密目录下面的子目录，就盖住整个私密目录，只把列的那个只读绑回来。范围-读的软链接被换过（真实路径和建的时候不一样）就不放。凭据目录（`~/.ssh`、`~/.config` 等）在放回的目录下也盖掉。
- 会话记录：只把这次运行自己的会话目录挂成可写，同一个定时任务之前运行的会话目录只读（分叉、续接要读），别的项目的看不到。每个定时任务单独一件事。
- 验证命令和运行在同一个沙箱里跑。

### 身份（第三轮复审 1，2026-11-23）

- 命令行（`tasks.py send/act/inbox/mr/diag`）一律不带主人权限，不管认出是谁。主人权限只来自 bridge 收到的 IM 消息，和服务从自己启动的运行的输出里解析出的内容（身份取任务记录）。
- 命令行要认是谁，只用来署名、找自己的收件箱。先问 bridge：bridge 开 unix 套接字 `state/ident.sock`（只给本用户），用 `SO_PEERCRED` 拿来访进程号。任务单元要过四关：cgroup 的完整路径等于 systemd 报的单元路径；任务在跑、轮次对得上；单元的 `InvocationID` 等于服务起它时记进任务记录的那个；进程是单元的 `MainPID` 或它的后代。写别的单元的 `cgroup.procs`、在自己 scope 下建同名子 cgroup、单元退出后起同名单元，都过不了（真 systemd 测过）。聊天、项目经理那一轮的 claude 和 popen 起的任务 runner，由 bridge 起进程时登记在自己内存里（进程号加启动时间），沿父进程找。都对不上就不认。
- bridge 不在时，命令行按同样的四关认任务单元。在服务单元里、或者 Linux 上有 systemd，认不出就拒绝，不按环境变量兜底。只有实例配置 `tasks.identity_fallback` 开着（默认 `auto`：没有 systemd 的机器才开，测试实例写 `true`）才兜底，只认在跑的任务。
- 主人专属的由服务执行：主控在主人私聊那一轮的回复里单独写一行 `[服务命令] diag [短名#N]`、`[服务命令] mr --repo <仓库> --branch <分支> --title <标题>`、`[服务命令] act <动作> --参数 值`，服务执行后把结果接着喂给同一个会话，最多两次，几段回复合在一起发。`act` 带幂等键（这一轮的消息、投递或任务回报，加命令，加第几次，记在 `state/service_acts.json`）：同一轮重跑拿上次的结果，不再执行；执行了但接着跑没成（超时、报错），结果直接发给主人，同一个会话半小时内再写同一条也拿上次的结果；执行到一半服务停了，不知道成没成，不重跑，说清楚。群里、同事那边、项目经理写的不执行。命令行 `tasks.py diag` 不给结果，只提示这个写法；`tasks.py mr` 只能从 `bot/` 分支建。主人自己发 `/status` 照旧。
- 投递记录由 bridge 写的才带签名（钥匙在 bridge 内存里，启动时生成）。主控、项目经理的投递轮只有签名对得上、发送方是主人，才按主人身份跑。命令行来的（`via: cli`）、任务进程直接写的、手写进 `records.json` 的、改过字的、送完又改回 new 的、bridge 重启前写的，一律按非主人送。
- 命令行投递叫起来的那一轮：`FCB_OWNER=0`；回复里的 `[派活]` 一律等主人批；`[任务指令]` 只能回给发来的那个任务，不改预算、不放开验收。
- runner 从输出里解析出的 `[投递]` 写进任务的 `marks.jsonl`，由 bridge 按任务记录的身份投（跟进展、提问走 `events.jsonl` 一样）。定时运行的还要过 `发给`。
- 主人答复会话发的请求：新建一条带签名的投递，落盘后才把原请求标成已回，没落盘就不标，让人再回一次；出错照投递的规矩重送最多 3 次。主人身份和私密只给一种情况：请求由主人自己的私聊会话（或它的项目经理）发起，记录是 bridge 写的、签名对得上，答复来自同一个私聊。其余的（同事私聊、企微同事私聊、群会话、同事触发的项目经理、主人在群里或换个渠道答复、请求是服务重启前写的、送到之前服务重启过）一律 `FCB_OWNER=0 FCB_PRIVATE=0`，答复文字照送，`[服务命令]` 不执行，`[派活]` 等主人批。会话的回话只发它自己的聊天或主人私聊，不发进别的群；改发主人私聊的，里面的 `[派活]`、`[任务指令]` 不执行。
- 答复任务的请求：先写收件箱（带幂等键），写成了再标已回；身份按答复人。
- `[任务指令]` 带幂等键：投递轮、任务回报轮重跑时，同一条不转两次；`[派活]`、项目经理的 `[投递]` 同样。
- CLI 发给任务的一律算留言。指令只来自服务解析的 `[任务指令]`。主人派的任务，这一轮不是主人触发的，只收留言。加预算、放开验收只认指令。

### 已知的残余风险

- 沙箱没开网络命名空间：抽象 unix 套接字连得上，本机所有 TCP 端口也连得上，包括只听回环的服务。后果：本机上没设口令的服务（数据库、开发服务器、调试端口、只听回环的管理接口）等于对定时运行开放，箱里能读写它们、借它们做箱外的事；箱里读得到的内容也能发到外网。这类服务自己要有口令，或者不跟机器人放在一台机器上。
- Claude 自己的登录凭据在沙箱里读得到（不然 Claude 跑不起来）。
- 装在家目录里的 MCP 服务器要写进 `tasks.sandbox_read` 才看得到。
- 没有 systemd 的机器（macOS）和测试实例按环境变量兜底认身份，主人身份一律不认。任务单元的 `InvocationID` 记在任务记录里，同一用户改得了（见“不防”）；记下之前的一瞬间，任务的命令行认不出。bridge 重启后，popen 起的任务 runner 的登记没了，这些任务的命令行只能走兜底。
- 沙箱里读得到 `config.json`（钩子要用）：里面没有密钥，但有主人和群的编号、私密路径的名字。
- 定时运行的 clone 读得到主仓库 `.git` 里的全部历史。
- 实例目录里的状态文件（任务记录、投递记录等）同一用户写得进去，`private_guard` 按文字拦，`cd 实例目录` 后用相对路径挡不住。身份和投递的主人身份不再信这些文件，任务记录本身（派活人是不是主人）仍是信任基础。
- 设备红线：包装脚本只在 PATH 里放了 `claude`、`node`、`npx`、`npm`、`pnpm`、`yarn`、`bun`、`bunx`、`deno` 的同名链接。写绝对路径（`/usr/local/bin/claude`、`/opt/homebrew/bin/node …`）或用别的解释器（`python -c` 起子进程）能绕过“按最终程序查”这一遍，只剩命令文字那一遍。在远程命令里先改 `PATH=…`（同名链接就找不到了），或者绝对路径加命令替换拼出程序名（`/usr/local/bin/$(printf cla)ude`），两遍都绕得过：命令文字里没有 claude 字样，也不经过同名链接。钩子那一道会把算不出的替换拦下，直接登录设备跑的拦不住。
- 设备钩子漏的：花括号和通配符拼的命令名（`d{e,}vcli`、`devc?i`）、`python -c`、写脚本再执行。会误拦的：heredoc 正文里当文字写的设备命令（例如用 `cat <<EOF` 写说明）、`cp`、`vim` 这类提到设备名的参数。命令超过 64 KB、或者套得太绕 10 秒查不完，按拦处理并说明原因。
- 不可逆闸门漏的：`uv publish`、`git send-pack`、`gh workflow run`（触发的流水线会发版）、`make release` 这类包在脚本和目标里的、`env -S '…'`。会误拦的：heredoc 里只是打印的 `npm publish` 等文字。

## 5. 私密资料（config.json 的 private）

- `paths`：正则列表。工具参数里出现就拦。默认样例拦个人事项目录、`.private`、Claude 的会话转录和历史。
- `search_roots`：知识库这类“大部分能看、少数分区私密”的目录。对整个目录的 `rg`/`grep` 自动加排除规则；`Grep`/`Glob` 工具和 `find` 等不能对整个目录用，要么换 rg，要么指定子目录。

要问用户的：
1. 哪些目录完全私密？（个人事项、证件、合同）
2. 知识库里哪些分区不能给同事看？（人物页、日记、草稿、对公司的私下分析）
3. 有没有不能让机器人读的聊天？

实例目录本身（代码、钩子、配置、状态、日志）由 scaffold 逐项加进权限拒绝表，机器人不能改；`private_guard` 再兜住实例目录里新建的文件。唯一例外是守则：主人私聊里机器人能改（行为偏好如汇报频率、说话方式都写在守则里，主人一句话就能调），其他场景照样拦。守则不能进拒绝表，拒绝规则压过一切，主人私聊里也会被挡。

## 6. 人设边界要点

**工作分身**最容易犯的错是拦太多。第一个实例上线当天，守则里“公司、部门、同事的讨论不能露”被理解成连项目都不让聊，主人的反馈是“这就是个工作群”。正确的划分：

- 正常聊：需求、方案、代码、进度、排期、谁负责哪块、bug。
- 不外露：人物资料、对人和组织的私下评价与深挖分析、主人的私下立场、主人私事。
- 判断标准：“这句话被当事人或当事人的领导看到，主人会不会尴尬。”

**私人助理**反过来：默认什么都不对别人说，只有通用问题能聊。

两种人设都要写清“哪些事要主人点头”，并给出用机器人身份私聊主人的命令。
