# 缓存：原理、验证、排查

## 1. 为什么要专门处理

每个飞书会话都是一个新的 `claude -p` 会话。Claude Code 只有工具定义和系统提示的静态部分能跨会话命中缓存。CLAUDE.md、skill 清单、记忆这些会话开头的上下文排在第一条用户消息前面，跟消息一起进缓存；消息每次不同，这一段（约 2 万 token）就每次重写。实测：不处理时一句“在吗”花 $0.18。

## 2. 模板已经做的四件事

1. **固定开场白**：新会话先用 `--session-id` 发一句固定的开场白，再用 `--resume` 发真正的消息。开场白每次相同，整段命中。新会话从 $0.18 降到约 $0.017，多 3–4 秒。`config.json` 的 `prime` 可关。
2. **`--exclude-dynamic-system-prompt-sections`**：把 cwd、环境、git 状态挪出系统提示。
3. **MCP 照用户级配置挂，等连上再开工**（`MCP_CONNECTION_NONBLOCKING=0`）。实测（2026-11-22，CLI 2.1.330）：
   - 根因：`claude -p` 默认不等 MCP 连上就发第一个请求。慢一点的服务器那一刻还是 `pending`，工具列表少几个，前缀就变了，约 1.8 万 token 要重写（5 个会话里 2 个）。
   - 设了这个环境变量后 CLI 先等连接：5/5 命中，每轮多等 0–3 秒。`--cache-check` 每轮打印各服务器状态，出现 `pending` 会标出来。
   - 连不上的服务器每次都是 `failed`，前缀照样稳定，但每轮要等到它超时（ssh 类约 8–28 秒）。这类时有时无的服务器别挂成 MCP，改用命令行按需调（例如 MCPorter 的 `mcporter call`，常驻进程连着，不进工具列表），谁能调由 `command_guard` 按人限制。
   - 续接的会话里，服务器掉线或重新连上，只多写几百 token，前面的上下文不重写。
   - 所有会话挂同一套 MCP，谁能用由 `hooks/mcp_guard.py` 按人拦，不靠给不同会话挂不同的服务器。`disable_mcp: true` 一个都不挂。
   - 聊天一轮用流式输出（`stream-json`），开场白用 `json`：输出格式不影响前缀，实测开场白和聊天消息照样全部命中。
4. **前文放在缓存前缀之后**：前文拼在消息里，同一会话只补新增的，不影响前缀。

多个渠道（飞书、企微）共用同一套参数、守则和开场白，缓存前缀跨渠道共享；渠道差异只放在每条消息的消息头里。不要按渠道拆守则。

## 3. 验证

```bash
python3 bridge.py --cache-check 3
```

连开 3 个新会话，每个“开场白 + 一句测试消息”，打印缓存读/写。正常时：

| 轮次 | 开场白（读/写） | 测试消息（读/写） |
|---|---|---|
| 1 | 约 1.2 万 / 约 2.5 万 | 约 3.6 万 / 几十 |
| 2 | 约 3.6 万 / 0 | 约 3.6 万 / 几十 |
| 3 | 约 3.6 万 / 0 | 约 3.6 万 / 几十 |

第 1 轮写入多是正常的（新内容首次进缓存，或缓存已过期）。第 2 轮起开场白写入仍上万，就是前缀在变。

上线后：`grep cost logs/bridge.log`。`session_total` 是会话累计花费，不是单次。

## 4. 排查前缀为什么变

1. 用 `--system-prompt-snapshot on` 跑两个新会话，转录（`~/.claude/projects/<workdir 编码>/<session>.jsonl`）里会有 `api-request-shape` 和 `api-request-blob` 行。
2. 去掉会话 ID 后 diff 两个会话的这两类行，不同的地方就是原因。
3. 常见原因：MCP 工具列表变化；守则或开场白刚改过；CLAUDE.md、skill、记忆刚改过；插件更新。
4. 在主会话的 shell 里测，子进程会继承父会话的环境变量，结果可能和服务里不同。用 `systemd-run --user --pipe` 按服务同款环境复现。

## 6. 2.0 新机制和缓存（2026-11-22 实测）

- 钩子配置不进缓存前缀。同一提示词，`--settings` 先用 1 个钩子、再用 5 个钩子（含 `matcher: "*"`），第二次 `cache_write` 0、`cache_read` 38583，和第一次的前缀完全一样（haiku，`claude -p --output-format json`）。所以 2.0 新加的 `device_guard`、`irreversible_gate`、`scope_guard` 和改过的 `task_inbox` 不会让缓存重写。
- 项目经理、定时任务、投递都不加启动参数：项目经理和聊天会话参数逐项相同，层次只放在环境变量 `FCB_LAYER`、`FCB_PROJECT`、`FCB_SESSION_KEY`、`FCB_SCHEDULE`、`FCB_SCOPE` 里，由钩子拦（验收测试 `test_project_manager_args_equal_chat_args`、`test_due_schedule_runs_as_scoped_ordinary_task` 锁住）。
- 定时任务的沙箱是 `bwrap` 包在 `claude` 外面，`claude` 自己的参数不变。
- 一次性变化：守则（`rules.md`）变长，新会话首条会多写一次。项目经理的工作要求在首条消息里，不在前缀里。
